# S2-06 - Integracion del endpoint de triaje con Cohere

## Objetivo

Conectar el endpoint `POST /api/triage` con un proveedor LLM para procesar documentos clinicos, validar la respuesta estructurada y devolverla junto con la informacion de almacenamiento en OCI.

## Flujo implementado

```text
Archivo multipart -> /api/triage -> memoria -> OCI Object Storage -> Cohere -> validacion JSON -> respuesta HTTP
```

El archivo recibido se lee en memoria. El backend lo almacena en OCI mediante `OCIStorageManager` y, cuando el proveedor Cohere esta habilitado, procesa el contenido clinico antes de construir la respuesta final.

## Componentes

- `mediflow/backend/app/api/routes.py`
  - Mantiene el endpoint `POST /api/triage`.
  - Valida nombre, extension, tamano y contenido del archivo.
  - Invoca `CohereClient.extract_document(...)`.
  - Integra la extraccion con la respuesta del servidor.
  - Devuelve `status: "procesado"` cuando la extraccion es valida.

- `mediflow/backend/app/core/llm_client.py`
  - Contiene `CohereClient`.
  - Construye el prompt clinico estructurado.
  - Realiza la llamada a Cohere mediante `/v2/chat`.
  - Procesa respuestas JSON del modelo.
  - Normaliza estructuras compatibles de paciente y profesional.
  - Procesa texto TXT, PDF, JPG, JPEG y PNG.

- `mediflow/backend/app/core/oci_client.py`
  - Contiene `OCIStorageManager`.
  - Sube el archivo recibido al bucket y prefijo configurados.
  - Se reutiliza tanto para el endpoint como para las pruebas de integracion.

- `mediflow/backend/app/models/schemas.py`
  - Define `TriageResponse` y los schemas de clasificacion, datos extraidos, enrutamiento y almacenamiento OCI.
  - Valida la respuesta final antes de devolverla al cliente.

- `mediflow/backend/app/core/config.py`
  - Define la configuracion del proveedor LLM, modelo de texto, modelo Vision, endpoint, API key y timeout.

## Formatos procesados

- `.txt`: se decodifica como UTF-8 y se envia al modelo Cohere de texto.
- `.pdf`: se extrae texto con PyMuPDF. Los PDF sin texto se convierten en imagenes para Cohere Vision.
- `.jpg`, `.jpeg` y `.png`: se envian como imagenes al modelo Vision configurado.

El procesamiento de PDF escaneados esta limitado a las primeras cinco paginas para controlar el tamano de la solicitud y el consumo de inferencia.

## Configuracion

La configuracion se define en `app/core/config.py` y puede sobrescribirse desde `mediflow/.env`:

```env
LLM_PROVIDER=cohere
COHERE_MODEL=command-a-plus-05-2026
COHERE_VISION_MODEL=command-a-vision-07-2025
COHERE_API_URL=https://api.cohere.com/v2/chat
```

La API key se mantiene como variable de entorno y no forma parte de la documentacion ni del codigo fuente.

La configuracion OCI utilizada para el flujo actual es:

```env
OCI_NAMESPACE=gra7f8gce282
OCI_BUCKET_NAME=recibidos
OCI_PREFIX_RECIBIDOS=pruebas/
```

## Dependencias

`mediflow/requirements.txt` incluye `PyMuPDF`, utilizado para extraer texto y renderizar paginas PDF cuando es necesario procesar contenido visual.

## Contrato de respuesta

La respuesta del LLM se incorpora a la estructura `TriageResponse` y contiene:

- `status`.
- `documento_id`.
- `clasificacion`.
- `datos_extraidos`.
- `decision_enrutamiento`.
- `notificacion_generada`.
- `almacenamiento_oci`.

La validacion se realiza mediante `TriageResponse.model_validate(...)` antes de devolver la respuesta HTTP.
